# 开发路线

## 现在

**v0.5 完成**（tag `peck-v0.5.0`，2026-11-13）。之后本地又按站主的意见做了一轮界面优化（Refine R4：左栏 AGENTS、CLI 选模型、LOG 挪进右栏、页签图标、左栏两块能收起，见 HANDOFF），等站主提交。云端可以开 v0.6（Phase 7 上下文、Phase 8 后台和 Monitor），站主的额度监测器作业同时开始。

## 定位

Peck 是只为站主、只在站主这台 Mac 上跑的个人 **Harness**：包在模型外面的那一层——把各家模型和 CLI 接进来（Model Gateway）、给模型手脚（工具箱）、管它看到什么和记住什么（上下文）、替它盯着验证命令（后台和 Monitor）、把这一切摆给站主看和审（界面）。不考虑多用户、跨平台、团队和云端 runner，放开用 macOS 本机的能力。不跑本地模型、不做云同步。

- **干活的是 Peck 自己的循环**：通过 Gateway 调任何 API 模型，带自己的工具箱和上下文管理。
- **CLI 是可换的引擎**：Claude Code、Codex、Muse、Grok 当整包引擎也能选，Peck 用它们的结构化接口显示每一步、替它们审批、记花费。**Antigravity 只做直接调用**（站主 2026-11-12 定，避开条款风险）。
- 主要借鉴 Pi（极简工具、钩子、会话树）、Codex（收件箱、按块审阅、独立工作区）、Claude Code Desktop（回合 recap、行内批注、后台任务）。调研在 visual-atelier 的 `canvases/peck-harness-questionnaire/research.md`。

## 怎么走

- **竖切**：每个版本做一条从头到尾能用的链路，装上就能用、能验。一个版本一到两个 Phase。
- **谁做**：看 Phase 表的「谁做」。默认云端开发、本地验收；站主指定的 Phase 本地开发。分工、Git、什么时候停下来问站主，都在 `CLAUDE.md`。
- **额度监测器是 Peck 自己的作业**：v0.6 起站主用 Peck 真实开发「额度与花费」（`src/quota/`、`src-tauri/src/quota/`），Agent 不写，只在每个版本的验收页里评估。
- **用 Peck 开发 Peck**：v0.7 以后。
- **视觉**：照 `src/vendor/peck/`（visual-atelier 方案 `peck` 同步来的，不手改）；新图标、新组件本地在方案里画、站主批、发新版本再同步。
