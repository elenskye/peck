# v0.5 开发计划：底座

> Phase 5 Model Gateway（**本地开发**）+ Phase 6 工具箱和 Peck 循环（云端开发）。依据是站主 2026-11-12 填的「[Peck Harness 问卷](https://claude.ai/artifact/1tXsLfFDZmfBB6WMCuVhF3)」和 visual-atelier 的 `canvases/peck-harness-questionnaire/research.md`。版本做完以后，结论并进 `architecture.md`、`design.md`，这份删掉。

## 装上 v0.5 以后能做什么

- 在一个**模型列表**里选谁来干：Peck 自己的循环配任何一家 API 模型（Anthropic、OpenAI、DeepSeek、阿里云百炼、Gemini、Vertex 上的 Claude 和 Gemini），或者一个 CLI 引擎（Claude Code、Codex、Muse、Grok、Antigravity）。顶栏不再分 CLI / API。
- 不管选谁，过程都是同一个样子：回答按 Markdown 显示，读了哪些文件、改了哪些、跑了什么命令折叠成一行，点开看每一步；要批的事弹卡片，模型要问你的事弹 ASK 卡片。
- Peck 自己的循环有了像样的工具箱：读、搜、改（整批原子）、跑命令（默认联网、只限制写到项目外）、任务清单、问你。
- 每轮下面一行花费，输入框旁是这个任务的累计，顶栏 QUOTA 能看到各家订阅还剩多少；花费上限到了会停。
- 输入框边打边渲染 Markdown；App 图标换成 J2，设置里能切回 A3。

## 不在 v0.5

上下文压缩、记忆、AGENTS.md（v0.6 Phase 7）；后台验证和自动修（v0.6 Phase 8）；收件箱、项目即环境、ⓘ 提示（v0.7 Phase 9）；代码上色、文件预览、行内批注、独立工作区（v0.7 Phase 10）；接力、委派、交叉审查、中途换引擎、Peck 接外部 MCP、V4A（v0.8 Phase 11）。现有的「Muse → Grok」「Grok → Muse」和 API 的「规划 + 实施」照旧能用，换到新的显示上，v0.8 再并进多引擎合作。

## 分工和顺序

```

M1 本地：Gateway 契约（约 1 天）──► 站主提交、推送 ──► Phase 6 改「进行中」
```

### 契约的约定（M1，2026-11-12 本地做好）

云端开工先读这几个文件，它们就是契约：`src-tauri/src/gateway/mod.rs`（两个接口、请求和回答、控制通道、错误）、`event.rs`（统一事件）、`caps.rs`（能力标记和各家初值）、`catalog.rs`（模型目录、价格、模型列表）、`src/lib/agentEvents.ts`（TS 对照）。

- **事件**：`AgentEvent` = `seq`（任务里从 0 递增）+ `at`（毫秒）+ 可选 `subagentId` + 事件本体（`type` 是 `session.started` 这样带点的名字，字段 camelCase）。引擎只经 `EventSink` 发事件：它编号、存进事件日志（原件另存一列，不发给界面）、再交给界面。读：IPC `gateway_events(runId)`。
- **用量口径**：`input` 是没走缓存的输入，`cacheRead`、`cacheWrite` 另算；`output` 包括思考，`reasoning` 是其中的思考。花费没有就是 `usd: null` + `source: unknown`，不填 0。
- **审批**：转换器只出 `approval.requested`；`approval.resolved` 由引擎那一层在站主回答（`Control::Approve`）以后发。四个选项统一成 `allow_once`、`allow_always`、`deny_once`、`deny_always`。`highRisk` 由 Peck 的规则（Phase 6 的 `risk.rs`）定，转换器一律填 `false`。
- **模型列表**：IPC `gateway_models`，每项的 `id` 就是发任务时的「谁来干」（CLI 引擎还带 `account`：当前账号名）：`api:<供应商>/<模型>`（Peck 循环 + 这个模型）、`cli:<引擎>`、`flow:muse>grok` / `flow:grok>muse` / `flow:plan-implement`（现有的接力和规划 + 实施）。`directOnly` 为真的（Antigravity）不进 ONE SHOT 和任何自动化。
- **Peck 循环怎么接**：`harness/` 实现 `AgentBackend`（引擎 id `peck`），里面用 `ModelProvider::complete` 调模型（对话用和供应商无关的 `Message` / `Part`，思考的私有数据挂在 `Part::Reasoning.opaque` 上，原样放回下一轮），自己跑工具，出同一套事件。
- **假 Gateway**（`gateway/mock.rs`）：`ScriptedModel::peck_demo` 是 Peck 循环的剧本（九个工具里的七个，最后一句收尾）；`ReplayBackend::fixture("codex" | "claude-code")` 回放录好的夹具，碰到审批、ASK 会停下等控制通道。浏览器 `?mock` 用 `src/dev/gatewayMock.ts`（模型列表和夹具事件都从仓库的夹具文件读，和 Rust 同一份）。
- **夹具**（`src-tauri/tests/fixtures/gateway/`）：`codex-small-task`（读、追加一行、跑一条命令，3 次审批）、`anthropic-tools-thinking`（一次工具调用、一次带签名的思考，两次请求的原文都在）、`claude-code-small-task`（同一个小任务，Haiku；`acceptEdits` 下这条命令没弹审批）；`models-mock.json` 是 `?mock` 的模型列表。`events.jsonl` 一行一条 `Emitted`（事件 + 可选的 `subagentId`，就是 `AgentEvent` 去掉 `seq`、`at`）。改了转换器、确认新结果对：`PECK_REGEN_FIXTURES=1 cargo test gateway` 重写期望文件。
- **Claude Code 的审批不用 MCP**（本地 2026-11-12 查到）：加 `--permission-prompt-tool stdio`，它把每次审批发成 stream-json 里的 `control_request`（`can_use_tool`），Peck 直接回 `control_response`（`convert/claude_code.rs` 的 `approval_reply`）。Peck 的本机 MCP 入口只剩 `ask_user` 和给别家 CLI 用。
- **设置**：IPC `gateway_config_get` / `gateway_config_set`，存 Vertex 的 Project ID、Location 和「CLI 目录」（Gateway 先在这个目录找 `claude`、`codex`、`agy`……，空着照 PATH 找）；界面在设置的「供应商和 Key」和「CLI 检测」。
- **数据库**：schema 7（`0007_gateway.sql`）：`agent_events` 表；`runs` 多一个 `engine` 列（旧任务为空）。
- **价格**：`node scripts/models-snapshot.mjs` 从 models.dev 重取 `src-tauri/defaults/models.json`；图标：`bash scripts/app-icons.sh` 重出 `src-tauri/icons/` 的 J2、A3（打包已经用 J2）。

## Phase 5 Model Gateway（本地）

### 统一事件

Peck 自己的循环和每个 CLI 引擎都转成同一套事件，界面只认这一套；每条事件在事件日志里存一份原件（`raw`），不认识的事件也不丢。

| 类 | 事件 | 要点 |
| --- | --- | --- |
| 会话 | `session.started`、`session.config_changed` | 带能力标记、模型、工具、MCP 状态 |
| 回合 | `turn.started`、`turn.completed` | 结束原因：做完、到上限、拒绝、取消、打断、出错 |
| 内容 | `message.delta` / `completed`、`reasoning.delta` / `completed` | 思考的私有数据（签名、密文）原样挂着，带来源（供应商、线协议、模型） |
| 工具 | `tool_call.started` / `output_delta` / `completed` | 种类：读、改、跑、搜、取网页、MCP、其他；改文件的带 Diff |
| 改动 | `diff.updated` | 回合级的汇总 |
| 计划 | `plan.updated` | 任务清单 |
| 交互 | `approval.requested` / `resolved`、`user_input.requested` / `resolved` | 审批选项统一成：这次允许、总是允许、这次拒绝、总是拒绝 |
| 子任务 | `subagent.started` / `completed` | 用父 id 关联 |
| 用量 | `usage.updated` | 输入、输出、缓存读、缓存写、思考、上下文占用；花费和它的来源：实报 / 按价格表估 / CLI 估 / 未知 |
| 额度 | `quota.updated` | 订阅窗口和余量（Codex、Muse、Grok），和美元分开，不相加 |
| 其他 | `notice`、`retry`、`error`、`raw` | |

### 能力标记

界面按它降级：能不能流式出字、思考能不能回放、工具归谁（Peck / 引擎）、审批（没有 / 预先配置 / 实时）、能不能中途追加和打断、能不能续接、能不能注入 MCP、用量粒度（每轮 / 累计 / 没有）、花费来源、有没有订阅额度、能不能切模型、要不要终端（TTY）。

### 模型目录和价格

- `src-tauri/defaults/models.*`：每个模型的 ID、供应商、线协议、显示名、上下文窗口、最大输出、思考档位、工具和看图支持、价格（输入、输出、缓存读、缓存写，每百万 tokens）、价格的日期。价格从 models.dev 取一份快照进仓库，设置里能改、能加模型（沿用现在的 `profiles.rs` 做法：能力要明确填，不按名字猜）。
- 花费：API 按实报用量 × 价格表算；CLI 报的标「估」；Claude Code 续接以后报的是累计，取差值；没价格的标「未知」，不填 0。

### API 七家

现在的 `request_once`、SSE、钥匙串、授权账本都保留，搬进 `gateway/providers/`。路由按「线协议 × 认证和地址」两个键。

| 供应商 | 线协议 | 认证 | 要点 |
| --- | --- | --- | --- |
| Anthropic | Messages | Key | 思考和签名块原样回传；缓存断点；缓存读写进用量 |
| OpenAI | Responses | Key | `store:false`，加密思考和 function_call 原样回传 |
| DeepSeek | Chat Completions（DeepSeek 方言） | Key | `reasoning_content` 回传 |
| 阿里云百炼 | Chat Completions（Qwen 方言） | Key + 地域 | `enable_thinking`；地域和 Key 一致 |
| Gemini | 原生 `streamGenerateContent`（替掉现在的兼容口） | Key | 调用工具那一段必须带 thought signature，不然 400 |
| Vertex 上的 Claude | Messages | gcloud ADC | 模型放 URL 里，body 加 `anthropic_version`（新值实测）；默认 `global` 端点 |
| Vertex 上的 Gemini | 原生 | gcloud ADC | 同 Gemini，换 Vertex 地址 |

- 思考块只在供应商、线协议、模型三样都一样时回放，换了就丢（为 v0.8 的中途换引擎留好）。
- Vertex 的令牌一小时过期，Gateway 自己刷新；读不到 ADC 时设置里写明「先跑 gcloud auth application-default login」。

### CLI 五家

都用结构化接口；没有结构化输出的才退回现在的纯文本清单（保留做兜底）。权限三档由 Gateway 映射成各家的参数，下表里标「实测」的以真跑结果为准，定了写进 `architecture.md`。

| CLI | 接口 | PLAN / EDIT / AUTO | 审批和 ASK | 用量和额度 | 续接 |
| --- | --- | --- | --- | --- | --- |
| Codex | `codex app-server`（stdio JSON-RPC），按本机版本生成 schema | 只读沙箱 / 可写工作区 / 可写工作区 + 网；审批一律交给 Peck 决定 | `requestApproval` → Peck 的规则和高危卡片；`requestUserInput` → ASK 卡片 | `thread/tokenUsage`、`account/rateLimits` | `thread/resume` |
| Claude Code | `claude -p --output-format stream-json --input-format stream-json --verbose`；用站主的订阅，**不加 `--bare`**，照平时读 CLAUDE.md、hooks、MCP | `plan` / `acceptEdits` / `acceptEdits` + 放宽的 `--allowedTools`（实测） | `--permission-prompt-tool` 指向 Peck 的 MCP 审批工具；ASK 走 Peck 的 MCP `ask_user` | `result` 里的花费（估，续接取差值）、用量 | `--resume` |
| Muse | `muse exec --json`（以后换会话协议） | 实测（`--disable-approval` 保留沙箱） | exec 没有审批回调：**高危拦不住**，靠 Muse 沙箱 + Peck 的快照和撤销兜底，界面写明；ASK 走 Peck 的 MCP | `run.usage`（tokens 和订阅余量） | `--session-id` |
| Grok | ACP（`grok agent stdio`） | ACP 的模式 / Peck 按档位回答 | `request_permission` → 规则和卡片；ASK 走 Peck 的 MCP（ACP 建会话时注入） | 用量事件；`grok usage` 取额度 | ACP `session/load` |
| Antigravity | ACP（`agy acp`） | 同 Grok | 同 Grok | ACP 用量 | 不做 |

- **Antigravity 只做直接调用**：只在 NEW TASK 和接着发的那一句里能选；不出现在 ONE SHOT、接力、委派、审查、定时任务、目标模式、自动修里；模型列表里标「直接调用」。
- 停止和打断：先发中断（ACP / app-server 的 interrupt，Claude Code 发 SIGINT），等它收尾，超时再结束整个进程组。
- 版本：检测时记下每家 CLI 的版本，和夹具的版本不一样时在设置里提示「格式可能变了」。

### CLI 账号（切换登录、重新验权）

站主 2026-11-12 要求：Claude、Codex 会有多个订阅，设置里要能切换登录、重新验权；**不同账号在浏览器、CLI、客户端里的登录互不干扰**（比如 Claude 客户端是账号 1、Claude 命令行是账号 2）。

- **一个账号 = 一个独立的配置目录**：Claude Code 用 `CLAUDE_CONFIG_DIR`，Codex 用 `CODEX_HOME`。本地实测（2026-11-12）：指向空目录时两家都显示「没登录」，和默认位置的登录互不影响。账号目录放「CLI 目录」旁边的 `accounts/<引擎>/<账号名>/`（`cli/bin` → `cli/accounts/…`），没设 CLI 目录就放 Peck 数据目录。
- **和客户端隔开**：Peck 驱动 CLI 时一律用自己的账号目录，不用 CLI 的默认位置——Codex 的默认 `~/.codex` 和 ChatGPT 客户端共用登录，Claude Code 的默认 `~/.claude` 和 Claude 客户端的 Code 页共用设置。站主想沿用默认位置，账号里可以选「默认目录」，界面写明会和客户端共用。
- **和浏览器隔开**：登录时不自动开默认浏览器（那里登着的账号会顶替），设置里显示登录链接和「复制」，站主自己挑浏览器、浏览器的另一个用户或隐身窗口去登；Claude Code 要粘回的 code 在设置里粘。Codex 也可以用 `--device-auth`。
- **设置 →「CLI 检测」**：每个引擎一组账号（名字、订阅类型、登录状态），按钮：新增账号、设为当前、切换登录（重新登录这个账号）、重新验权（只跑 `claude auth status` / `codex login status`，不发模型请求）、删掉（删它的配置目录，先确认）。模型列表里 CLI 引擎后面显示当前账号名；每个任务记下用的是哪个账号。
- 登录在 Peck 的伪终端里跑 CLI 自己的登录命令；Peck 只设环境变量、读状态命令的输出，**不读、不复用任何凭据**。
- 取舍：独立配置目录下 Claude Code 不读 `~/.claude` 里的用户级设置、MCP 和 CLAUDE.md（项目里的照读），需要的话复制进账号目录。Grok、Muse、Antigravity 看各家有没有类似的目录变量，有就一样做，没有先只支持默认账号。

### Peck 给 CLI 的本机 MCP 入口

- App 里起一个只听 `127.0.0.1` 的 MCP 服务（streamable HTTP，每个任务一个随机令牌），工具 `ask_user`（任何引擎问站主）；需要的引擎再加 `peck_approve`（Claude Code 改用 stdio 审批，见「契约的约定」）。以后加记忆、委派。
- 启动 CLI 时把它加进去，不覆盖站主自己的 MCP 配置：Claude Code 用 `--mcp-config`（不加 `--strict-mcp-config`），Codex 用 `-c mcp_servers.peck…`，Muse 用它的 `mcp_servers` 设置，ACP 在建会话时传 `mcpServers`（各家参数实测）。

### 事件日志

迁移 `0007_gateway.sql`（schema 7，升级前照旧自动备份）：`agent_events`（任务、步骤、序号、时间、引擎、种类、统一后的内容、原件），按任务和序号建索引；任务记录多一个引擎字段。旧任务照旧按旧记录显示。

## Phase 6 工具箱和 Peck 循环（云端）

### 循环

- 新模块 `src-tauri/src/harness/`（`loop.rs`、`tools/`、`permission.rs`、`risk.rs`、`spill.rs`），从 `api/worker.rs` 搬过来，改成通过 Gateway 的 `ModelProvider` 调模型、产出统一事件。「规划 + 实施」（`supervisor.rs`）照旧能用，接到新循环上。
- 上限：默认 40 轮；上下文用到模型窗口的 85% 先停下告诉站主（压缩是 v0.6）；花费上限到了在下一次请求前停；用量未知照旧停下。旧的 18 万字节、12 轮上限去掉。
- 失败、取消、重开不自动重发，照旧。

### 九个工具

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `list_directory` | `path`（默认项目根）、`depth` 1–3 | 遵守 .gitignore，最多 300 条，超了说明截断 |
| `read_file` | `path`、`start_line`、`line_count`（最多 2000） | 带行号（6 位右对齐 + tab），最多 50KB，截断时写「共 N 行，下次从第几行」；记下读到时的修改时间和哈希；能读 Peck 落盘的命令输出 |
| `search_text` | `pattern`、`path`、`glob`、`regex`（默认否）、`mode`（文件 / 内容 / 计数）、`context`、`max`（100）、`offset` | 进程内用 ripgrep 的库（`ignore`、`grep-searcher`），遵守 .gitignore |
| `find_files` | `pattern`（glob）、`path` | 按修改时间排，最多 100 条 |
| `write_file` | `path`、`content` | 新建或整个覆盖；覆盖已有文件前必须在这个任务里读过、且哈希没变 |
| `write_patch` | `edits: [{path, old_text, new_text, replace_all}]` | 「找原文 → 换新文」。整批先校验，写临时文件再改名，任何一处失败就一个都不写；找不到时给最像的几行和空白差异，找到多处时列出行号；可以宽松匹配（行尾空白、中英文标点），但必须仍然唯一，并在结果里写明；返回每处改动前后 3 行 |
| `bash_run` | `command`、`cwd`、`timeout_sec`（默认 120，最长 600） | 沙箱：**默认联网**，只能写项目、临时目录和 Peck 给的 HOME；用站主 shell 的环境（`term.rs` 读的那份）；stdin 接空，设 `CI=1`、`PAGER=cat`、`NO_COLOR=1`；输出超过 16KB 整份落盘，上下文只留开头 2KB、结尾 6KB 和路径，失败时优先留结尾；grep、diff 的退出码 1 不算失败 |
| `update_plan` | `steps: [{text, status}]` | 同时只有一步在做；界面里是任务清单（替掉 Peck 循环里的 `.peck/tasks.md`） |
| `ask_user` | `question`、`options` | 弹 ASK 卡片，等站主答；Peck 不在最前面时发通知 |

`memory` 工具和「提议后批」放在 v0.6 Phase 7，和记忆一起做。

### 权限三档和高危

| 档 | Peck 循环里 |
| --- | --- |
| PLAN | 只给读的工具、`update_plan`、`ask_user`；`bash_run` 在只读沙箱里跑 |
| EDIT（默认） | 全部工具；装依赖（npm / pnpm / cargo add / pip / brew 这类）、起常驻进程前问一次，能选「这个项目总是允许」 |
| AUTO | 全部工具，除了高危都不问 |

- **高危不管哪档都弹卡片**：删文件（`rm`、`git clean` 这类）、推送和改历史（`git push`、`reset --hard`、`branch -D`、force）、写到项目外（沙箱拒了就弹卡问要不要出沙箱再跑）、改系统设置（`sudo`、`defaults write`、`launchctl` 这类）。规则放 `risk.rs`，每条有测试。
- CLI 引擎的档位由 Gateway 映射（Phase 5），弹的卡片和这里是同一套界面。

### 界面

- **谁来干**：输入框下面一个模型列表（`pk-menu`），分两组：Peck（API 模型，按供应商，只列配了 Key 的）、CLI 引擎（只列检测到的，Antigravity 标「直接调用」）；现有的 Muse → Grok、Grok → Muse、规划 + 实施作为列表里的几项保留。支持思考强度的模型旁边一个强度选择。顶栏去掉 CLI / API 切换。
- **过程**：回答用 Markdown；思考折叠成「思考 · 12s」；连续的工具调用折叠成一行（「读了 4 个文件、改了 2 个、跑了 1 条命令 · 38s」），在跑的那一步露出来，点开每一步一行（读、改带 Diff 入口、跑带退出码）。Peck 循环和 CLI 引擎同一套。
- **卡片**：高危审批（批准、不行；不是高危的询问多一个「总是允许」）、ASK（问题 + 选项 + 自己写）、任务清单。
- **Markdown**：回答和站主发的话都渲染（标题、列表、引用、表格、行内代码、代码块；代码上色等 Phase 10）；输入框换成能边打边渲染的编辑器（CodeMirror 6 加 Markdown，样子照 Peck），⌘↵ 发送、中文输入法、关自动改字都照旧。
- **花费**：每轮回答下面一行（进、出、缓存命中、花费，CLI 的标「估」）；输入框旁这个任务累计；顶栏 QUOTA 的用量页多出 Gateway 读到的订阅余量。设置里的花费上限这一版真正生效。
- **ONE SHOT**：右栏页签能用了：选一个引擎（API 模型和 CLI，Antigravity 除外），按 PLAN 档只读回答，不锁终端，答完一行花费。
- **App 图标**：默认 J2；设置 → 外观多一行「App 图标：J2 / A3」，切了 Dock 里马上换（访达里的图标还是 J2）。
- 新的界面零件照 `src/vendor/peck/` 的现有组件拼（Menu、Ask、Steps、Toast、Field）；方案里没有的样子取沉静的那一边，记进 HANDOFF 交给本地改方案。

### `?mock` 和测试

- `?mock` 用 Phase 5 的假 Gateway：一个 Peck 循环的剧本（读 → 搜 → 改 → 跑命令 → 清单 → 问一句 → 收尾）、Codex 和 Claude Code 的夹具回放、高危卡片、花费行和上限停下。

## 验收点（本地出验收页用）

**Phase 5（本地开发，真跑）**

1. 模型列表里有配了 Key 的 API 和检测到的 CLI；Antigravity 标「直接调用」。

5. 让 CLI 删一个文件：Codex、Claude Code、Grok、Antigravity 弹高危卡片，拒了它就不删；Muse 写明拦不住。
6. Claude Code 或 Codex 问一个问题：弹 ASK 卡片，答了接着做。
7. 顶栏 QUOTA 看得到 Codex、Claude Code、Muse、Grok 的订阅余量。

**Phase 6（云端开发）**

12. 三档：PLAN 不改文件；EDIT 装依赖问一次、能「总是允许」；AUTO 不问；高危都弹。
13. 跑一条输出很多的命令：模型拿到头尾，完整日志能点开。
14. 工具调用折叠成一行，点开每一步。
