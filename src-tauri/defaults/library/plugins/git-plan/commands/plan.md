---
description: 给一个新版本写 Phase 计划（先不动代码）
argument-hint: <版本> <要做的事>
---
按 git-plan 这个 Skill 的规矩，给这个项目写一份 Phase 计划。先读 Skill 全文和项目的说明文件。

要做的：$ARGUMENTS

1. 版本号没写就按要做的事判断该升 y 还是升 z，跟站主确认；只是修 Bug、小优化（升 z）的不用分 Phase，直接说一声就可以开工。
2. 读相关的代码和文档，弄清现在是什么样、要改哪些地方。拿不准的决策点先问站主。
3. 分成几个 Phase，每个写清**做什么**和**怎么算做完**（能查的条目），按能独立做完、验完的顺序排。另写一行「不做什么」。
4. 写进项目的路线文档（有 `docs/roadmap.md` 这类就用它，没有就问站主放哪）。
5. 停下来请站主看，站主说可以再开始第一个 Phase。这一步不改代码。
