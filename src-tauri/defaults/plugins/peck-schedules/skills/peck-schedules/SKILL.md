# 定时任务

到点了 Peck 替站主在**这个项目**里发一句话，像站主自己发的一样跑一个任务。定时任务只在对话里设、改、取消；界面上只在 PROJECTS 头上列出来看。

## 把一句话拆成两样

站主说的话里有两样东西：**什么时候**，和**到点做什么**。

| 站主说 | repeat | 其余 |
| --- | --- | --- |
| 每周一早上九点 | `weekly` | `days: [1]`，`time: "09:00"` |
| 每个工作日早上八点半 | `weekly` | `days: [1,2,3,4,5]`，`time: "08:30"` |
| 每天晚上十点 | `daily` | `time: "22:00"` |
| 每月 1 号早上九点 | `monthly` | `day_of_month: 1`，`time: "09:00"` |
| 每隔两小时 | `interval` | `every_hours: 2` |
| 明天下午三点（只一次） | `once` | `date: "YYYY-MM-DD"`，`time: "15:00"` |

- 时间是站主这台 Mac 的本地时间，24 小时制。`days` 里 1 是周一，7 是周日。
- 「明天」「下周五」要换成具体日期：现在的本地日期、时间、星期几写在 `<peck-context>` 的 Local time 里；没有这一行就跑一下 `date`。
- 没说几点（「每周一帮我检查依赖」）：问一句几点，不要自己猜。
- 一个定时任务只有一条时间规则。「周一和周四各一个时间」设两个。

**到点发的那句话（`prompt`）**要自己能读懂：到时候是一个新对话，没有现在的上下文。把「它」「刚才那个」换成具体的东西，把要的结果写进去。例如站主说「每周一早上九点帮我检查依赖更新」，`prompt` 写成「检查这个项目的依赖有没有可以更新的版本，列出能升的和升级风险，先不要改文件」。站主没说要不要动手的，默认写成只检查、只汇报；要它改的才写改。

`title` 起一个几个字的名字（「依赖更新」）。

## 设之前先复述、等确认

调 `schedule_task` 之前，用一两句话把四样说给站主听，等站主说可以：

> 我设一个定时任务：**每周一 09:00**，在这个项目里发「检查这个项目的依赖有没有可以更新的版本，列出能升的和升级风险，先不要改文件」，用现在选的 Codex 跑，每次开一个新对话。可以吗？

站主改了哪一样就按改的再复述一次。确认了再调。

## 谁来干、在哪跑、权限

- **谁来干**：不写 `who`，就是站主现在在 AGENTS 里选的那一套（接力、审查也带着）。站主话里点了名（「用 DeepSeek 跑」「让 Codex 做」）才写 `who`，写站主说的名字。对得上不止一个模型时工具会把候选列回来，问站主要哪一个。
- **在哪跑**：默认每次开一个新对话。站主说了「接在这个对话里」「就在这里跑」才写 `conversation: "this"`。
- **权限**：默认 AUTO（到点没人看着，要能自己做完）；删文件、推送这类高危的照样停下等站主批。站主要它只看不动才写 `permission: "plan"`。

## 看、改、取消

- 看：`list_schedules`，把每个的名字、什么时候、下一次、谁来干念给站主。
- 改时间、改那句话、换谁来干：先 `list_schedules` 拿到 `id`，再调 `schedule_task` 带上 `id` 和改后的整套规则（`prompt`、`repeat` 和时间都要重写一遍；不写 `who` 就不动原来的）。改之前同样复述确认。
- 取消：`cancel_schedule {"id": "…"}`。对不上是哪一个就先列出来问。

## 站主会问到的

- Peck 开着才跑；关着错过的不会自己补跑，重开 Peck 时在这个项目里弹一张卡片，站主点 RUN NOW 或 SKIP。重复的任务错过好几次也只有最近那一次的卡片。
- 到点时这个项目正好有任务在跑，会等它跑完再发；等了两小时还在跑就算错过。
- 一个项目最多 12 个。只跑一次的跑完就没有了。
