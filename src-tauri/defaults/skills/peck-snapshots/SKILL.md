# 任务快照：看改动、反悔

Peck 在每个任务开始前、结束后各存一份项目文件的快照（存在 Peck 自己的影子仓库里，不动站主的 Git）。以前站主在界面上点「撤销」，现在跟你说一声，你用 `restore_snapshot` 做。

## 什么时候用

- 站主说撤销、反悔、回退、恢复、放回去、「回到……之前」「刚才那次不要了」。
- 站主问最近几次任务改了哪些文件（只要 `action: "list"`，不回退）。
- 你自己觉得改坏了：**不要**自己回退。告诉站主哪里坏了，问要不要回退。

不用它的情况：站主要看某个文件具体改了什么，用 `read_file` 读现在的内容、`search_tasks` 看那次任务的记录；这个任务里你自己刚改错的一两处，直接改回来就行。

## 步骤

1. **先列出来**：`restore_snapshot {"action": "list"}`。每行是一个任务：任务号、时间、当时要做的事、改了哪些文件、有哪些状态（before / after）。
2. **对上是哪一次**。站主说「刚才」「上一次」一般是列表里最新的、状态不是 running 的那一次；说不清是哪一次、或者对得上两次以上，就把候选的几行念给站主，问清楚。
3. **跟站主复述、等确认**：一两句话说清楚要做什么。例如：「要把任务 159（改登录页）改过的 3 个文件放回它开始前的样子：`src/login.ts`、`src/api.ts` 写回，`src/new.ts` 删掉。可以吗？」站主在对话里说了可以再调。站主的原话已经把哪一次、回到哪里说得很明确（「把任务 159 撤掉」），复述一句就可以直接调，卡片上站主还会再批一次。
4. **回退**：`restore_snapshot {"action": "restore", "task": 159, "to": "before"}`。Peck 会弹一张高危卡片列出要动的文件，站主批了才动；没批就什么都不动，告诉站主没动，不要换个办法绕过去（比如自己用命令删文件）。
5. **说结果**：写回了几个、删了几个；提醒一句回退前的样子也有快照，想放回来说一声。

## to 选哪个

- `"before"`：回到那次任务**开始前**，等于撤销它。
- `"after"`：回到那次任务**结束后**。用在「刚才撤销的再放回来」（重做），或者「后来又改乱了，回到那次刚做完的样子」。

## 只回退一部分文件

站主只想放回某几个文件（「只把 a.ts 放回去，别的留着」）：加 `paths`，写相对项目的路径，文件或文件夹都行。

```json
{"action": "restore", "task": 159, "to": "before", "paths": ["src/login.ts", "docs"]}
```

- 只会动这个任务改过、现在和那时不一样的文件；`paths` 里不在范围里的会在卡片上写「不动」。
- 只回退一部分不会把那次任务标成「已撤销」。
- 站主只想放回一个文件里的某一段：快照按整个文件放回，做不到一段。先 `read_file` 读现在的文件，直接改那一段。

## 要回退好几次任务

- 默认只动**那一次任务改过的文件**，后来的任务、站主自己改的别的文件不动。连着撤几次，就从最新的那次开始、一次一次往回（每次一张卡片）。
- 站主明确要「整个项目回到任务 N 之前，后面的全不要」：`"scope": "project"`。这会把之后每一次任务的改动、站主自己后来改的也一起放回去，复述时要把这一点说出来。

## 回退不了的情况

- 还在跑的任务（包括现在这一个）没有能回去的快照。
- 在独立工作区（WORKTREE）里做、还没搬回的任务：项目里没有它的改动，不用回退；不要它就请站主点 DISCARD。
- 那次任务没做完就停了：只有 before，没有 after。
- PLAN（只读）下不能回退：请站主换成 EDIT 或 AUTO。
